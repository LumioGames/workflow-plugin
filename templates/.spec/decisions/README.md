# Decisions（决策记录 · ADR）

本目录是全仓决策的**唯一落点**：为什么这样划边界、为什么选这个方案、为什么否掉别的。功能文档只描述设计现状，不留决策记录。

## 怎么写一条 ADR

- 一个决策 = 一个文件 `ADR-NNN-<slug>.md`，编号从 `001` 递增、同目录不得撞号；写完在下方索引加一行（`/workflow:lint` 校验登记与撞号）。
- 前 12 行内必须有状态行 `状态：X`，X 取 `Draft` / `Accepted` / `Superseded`。`Draft` 可随实现验证修订；`Accepted` 后不改写，要推翻就新增一条并把旧的标成 `Superseded（被 [ADR-NNN](ADR-NNN-<slug>.md) 取代）`。
- 无 frontmatter。格式照抄：

  ```markdown
  # ADR-NNN：<一句话决策>

  状态：Draft
  日期：YYYY-MM-DD

  ## 背景
  面对什么问题（大白话）。

  ## 决策
  定了什么。

  ## 替代方案与否决理由
  还考虑过什么、为什么不选。

  ## 兼容影响
  哪些文档 / 代码要跟着改（点名的知识文档须回指本 ADR 编号）。
  ```
