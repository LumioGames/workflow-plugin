# 受测环境与测试账号

本文件只管一件事：**这次到底在哪个地址、用什么身份跑测**。跑错环境的验收结论比没有结论更危险——它会让一个真 bug 被关掉。

Workflow 侧的连接、凭证、项目一致性仍以 [workflow-ops 的 connection.md](../../workflow-ops/references/connection.md) 为单一真相源，本文件不重复。

## 一、受测环境从哪来

按顺序解析，**取到第一个就停**：

1. **用户当场指定**的线上地址（本次会话内有效，优先级最高）。
2. **`.workflow` 的 `[qa]` 表**：与 `profile` 同一个文件、同一套查找规则（从当前目录向上逐级找最近的一个，到含 `.git` 的目录或文件系统根为止）。
3. **都没有 → 停下问用户**，不猜、不用仓库里出现过的任何地址推断。问到之后主动提议写回 `.workflow`，让下次和队友都不用再问。

## 二、`[qa]` 表的字段

`.workflow` 顶层仍**只有** `profile` 一个键；`[qa]` 是可选表，**不含任何凭据**，只声明环境变量名，因此可以提交进版本库与全队共享。

```toml
profile = "<profile 名>"

[qa]
base_url = "https://<线上站点>"          # 必填：受测线上根地址
entry_path = "/<登录或入口路径>"          # 可选：固定入口，缺省从 base_url 进
username_env = "<用户名环境变量名>"       # 可选：需要登录时必填
password_env = "<密码环境变量名>"         # 可选：需要登录时必填
surfaces = ["web"]                       # 可选：受测面，如 ["web", "desktop"]
forbidden = ["<本项目禁止的操作>"]         # 可选：项目自定的红线，逐条并入 Q5
```

解析纪律：

- **只读不写**：本技能不改 `.workflow`；要写回时给出内容让用户确认后再写。
- **`[qa]` 存在但 `base_url` 解析不出** → 停下回显该文件内容让用户修，**不回落**到任何默认值。理由和 profile 解析落空一样：静默用错地址正是这套机制要防的唯一一件事。
- `forbidden` 里的每一条都当作 Q5 的项目级补充红线，与内置红线取并集。

## 三、测试账号

- 凭据**只**从 `username_env` / `password_env` 指名的环境变量读取（对应 Q4）。
- 变量缺失 → **停下，要求用户在本机环境里配置**。不要让用户把密码贴进对话——贴进来就进了会话记录、日志和可能的截图。
- 值不进命令行参数、不进日志、不进截图、不进评论、不进最终报告。需要指代账号时只写脱敏标识（如「测试账号 A」或邮箱前两位 + `***`）。
- 只用用户提供的测试账号。**不批量注册账号、不借他人账号、不动真实用户数据。**
- 会话里已登录的身份与目标测试账号不一致时，先退出再用目标账号进入；不要在别人的身份上做验收。

## 四、进入受测环境的开场三件事

1. **锁地址**：打开 `base_url` + `entry_path`，核对地址栏的 scheme、host、port、路径与声明**完全一致**。对不上就停（Q1）。
2. **锁身份**：确认当前账号具备本次验收所需的可见范围与权限；权限不足判「阻塞」，不提权、不换号绕。
3. **记基线**：记下验收时间（含时区）、最终业务页 URL、客户端版本或构建号（页面能看到就记）、视口尺寸。这四项后面要写进回写模板。

连不上、TLS 告警、登录失败或页面不可用 → 结论「阻塞」。**不得降低安全设置绕过**（不忽略证书、不关校验、不改 hosts）。

## 五、受测面与工具可用性

| 受测面 | 需要的能力 | 不可用时 |
| --- | --- | --- |
| `web` | 浏览器自动化（导航 + 快照 + 截图） | 判「阻塞」，不用 curl 冒充可视验收 |
| `desktop` | 桌面 UI 自动化 | 降级为 web-only，并在报告与评论里**明确声明这一缺口** |

接口请求、日志、源码、历史记录**只能补强解释，不能替代**可视操作与本次截图（Q3）。

单据涉及账号、登录、余额、同步等跨端能力且 `surfaces` 声明了多个面时，同一测试账号每个面各验一遍——「仅 A 面复现 / 仅 B 面复现 / 双端复现」本身就是重要定位信息，写进评论。
